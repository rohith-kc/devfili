# DevFili decisions log

Format: decision, why, date.

## Phase 2

- **Dropped the `zod-to-json-schema` dependency; use zod v4's native `z.toJSONSchema()` instead.** Tested directly: against our installed `zod@4.6.7`, `zod-to-json-schema@3.25.2` silently produces an empty schema (`{"$schema": "..."}`, no `properties`, no `required`) because it reads zod v3's internal `_def` shape, which v4 no longer has. `z.toJSONSchema()` produces the correct shape and - for a plain `z.object()` - already sets `additionalProperties: false`, exactly what Groq's `json_schema: {strict: true}` mode needs for `DraftCore`/`DraftPath`. (2026-10-24)

- **`verdict.gates.customerAdmin` (and `tile.customerAdmin`) is derived by code from `DraftCore.facts.customerAdminLikely`, overriding whatever `DraftPath.gates.customerAdmin.applies` the model drafted.** `docs/SPEC.md` section 7 (`tier.ts`) is explicit that this gate state "comes from `facts.customerAdminLikely`", which is a code-decides rule consistent with `CLAUDE.md`'s "the model never decides ... difficulty tier ... Code does." But `docs/PROMPTS.md` P4 also has the model draft its own `gates.customerAdmin.applies` independently, which could disagree with the fact. Finalize keeps the model's `who`/`what` prose and claims for that gate (descriptive text, not a yes/no/unknown decision) but always recomputes `applies` from the fact. (2026-10-24)

- **Turned off `cacheComponents`/`partialPrefetching` in `next.config.ts`** (both scaffolded `true` by default by this Next.js 16.4.3 create-next-app template). "Cache Components" makes `export const runtime`/`export const dynamic` route-segment config - which `docs/SPEC.md` section 2 explicitly requires on every route handler - a build error ("not compatible with nextConfig.cacheComponents"). Turning it off restores the traditional, spec-compliant route config instead of redesigning every route around the newer caching model. (2026-10-24)

- **Live CLI verification (complete guides for Linear, Zoom, and an unfamiliar app from `npm run research`) is pending, not done, as of this commit.** Both providers' free tiers are exhausted from this session's own testing: Groq's `openai/gpt-oss-120b` daily token budget (200,000 TPD) is used up (confirmed via repeated live runs, not a code bug - the pipeline mechanically completed resolve, discover [including its JSON-repair fallback], and probe correctly before hitting the 429 on the draft stage), and Gemini's `googleSearch`/`urlContext` grounding tools are separately `RESOURCE_EXHAUSTED`. The code itself is finished and covered by unit tests that mock every provider call (discover's parallel-call merge/dedupe/id-assignment, its JSON-repair path, its Gemini-fails-twice-so-fall-back-to-Groq path; draft's Groq-strict-then-Gemini-JSON-mode fallback; check's batching, provider fallback, and 40-claim cap; finalize's full assembly including the customerAdmin override). **Before Phase 2 is actually gated closed, run `npm run research -- "<app>"` against Linear, Zoom, and one unfamiliar app (e.g. Calendly) once quota resets, and confirm a stage timing log shows the whole run finishing under `RESEARCH_DEADLINE_SECONDS`.** (2026-10-24)

## Phase 3

- **`groqBrowserSearch`'s `max_completion_tokens` raised from 4000 to 8000.** A live Zoom generation showed the community discover call spend 57,933 total tokens (mostly the tool's own internal search/visit rounds) and still get its final JSON answer cut off mid-stream at the 4000-token cap, producing unparseable output that even the repair call couldn't recover (it legitimately had no complete findings to extract). 8000 gives the model room to finish writing its JSON after browsing. (2026-10-24)
- **Library generation is blocked on the same exhausted Groq/Gemini free-tier quota as Phase 2's live verification**, confirmed again live: a single successful `discover-community` call for Zoom used ~58k of the ~200k daily token budget by itself, so generating all 9 library guides (2 discover calls + 2 draft calls + up to 2 check calls each) will need either a much larger daily budget, several days spread out, or a paid tier. `scripts/library-generate.ts`, `scripts/library-validate.ts`, and `scripts/library-links.ts` are written and type-checked but have not yet produced a real `content/library/drafts/*.json` file. (2026-10-24)
